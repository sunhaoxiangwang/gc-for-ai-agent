## Decisions and deviations

Where the prompt was ambiguous, the more conservative reading was taken and the
choice is recorded here.

**Environment.** The machine had no Rust toolchain. Installed via rustup
(stable, `--no-modify-path`); `~/.cargo/bin` must be on `PATH`. Reversible with
`rustup self uninstall`.

**Extra dependencies beyond section 8.** `serde_json` (the `--json` schema, the
run manifest and heartbeat files all need it) and `predicates` (a dev-dependency
of `assert_cmd`). Avoided `uuid` (quarantine names are pid + nanoseconds +
counter) and any date-time crate (`time::rfc3339` and `parse_rfc3339` are about
80 lines of Hinnant civil-date arithmetic).

**`require_ancestor` semantics.** Read as symmetric with `require_sibling`: an
entry with that name must exist in *some ancestor directory* of the candidate,
from its parent up to and including the root. The alternative reading (an
absolute path the candidate must sit under) is already expressible with `glob`.

**`orphaned_only` semantics.** Read as requiring *positive evidence* of
orphanhood: the heartbeat directory must be readable and nothing in it may claim
the path. A missing or unreadable heartbeat directory rejects rather than
passes, which is the opposite of the default rule behaviour where absence of a
heartbeat means unprotected.

**`min_idle` default.** Path rules that omit it get 24h rather than 0.
A forgotten field should land on the safe end of the range.

**Machine overlays** override `[global]` keys only; they cannot add roots or
rules. Cross-machine portability comes from a root that does not exist being a
warning that is skipped, not an error.

**`reap-core` depends on `reap-platform`** for the trait definitions the guard
stack needs (`ProcessInspector`, `Volume`, `GitOracle`). It contains no
platform-conditional code of its own. `tests/invariants.rs` scans the crate
source and fails on any filesystem write call, any `unsafe`, and any
`std::process::Command`, which is why the git oracle had to move into
`reap-platform` even though it is not platform-specific.

**Symlink-component scan scope.** Invariant 2 says to reject any path containing
a symlinked component. The scan runs from the *declared root downwards*, not
from `/`. Above the root it would reject every macOS machine, where `/tmp` is a
symlink to `/private/tmp`, without adding safety: containment is decided by
comparing canonical forms, so a symlink above the root cannot move a candidate
out of the root. A symlink below the root can, and that region is scanned one
component at a time. Also documented in `docs/safety-model.md`.

**Deny floor additions.** Beyond the four the prompt names, the floor also
refuses any path containing a `.git`, `.ssh`, `.gnupg`, `.aws`, `.kube` or
`.password-store` component, and exact matches on the usual system directories
and the standard directories directly under `$HOME`.

**`--apply` with `dry_run = true` exits 2.** The prompt does not say what this
should do. Exiting 2 (config error) rather than 0 was chosen so a scheduler unit
that was never armed shows up in `systemctl status` instead of silently
succeeding forever. The run still prints the full dry report first.

**`gc-session` works through rules, not through heartbeat paths.** A session
workspace is not removable because a heartbeat named it; it is removable because
a configured rule names it and every guard permitted it (invariant 1). The
session id narrows the selection: a candidate belongs to the session if the id
is one of its path components, or if it is under a path the session's heartbeat
claims. `gc-session` also does not run command reclaimers, which are
machine-wide and would be a surprise on a single job's exit.

**launchd label and dist filename.** The prompt lists
`dist/launchd/io.github.OWNER.reap.plist`. The shipped file is
`dist/launchd/io.github.reap.plist`, and the label is `io.github.reap`
everywhere, because `reap install` and the hand-install template must agree: if
they used different labels, `reap uninstall` would not find a hand-installed
agent. A template whose label still says OWNER is also a file that does not work
when copied.

**APFS snapshot slack applies only when snapshots exist.** `Context::pressure`
adds `apfs_snapshot_slack_gb` to available space only when
`tmutil listlocalsnapshots` reports at least one snapshot, so a machine with
Time Machine disabled is never told it has 20 GB it does not have. On Linux the
snapshot list is always empty, so the slack never applies. `doctor` and
`sweep --until-free` read the same helper, so they cannot disagree.

**`sweep --until-free` without `--apply`** shows the full escalation through all
three tiers once and stops, rather than looping: nothing was freed, so
re-checking free space between tiers would report the same shortfall three
times.

**README output is real, captured from a purpose-built machine.** Every block in
the README was produced by running the actual binary. To satisfy both "show real
output" and "no private hostname, username or project name", the runs used a
demo home directory with generic project names, `REAP_HOSTNAME=workstation`, and
`--no-color`. The sizes are real allocated bytes, not invented figures.

**`REAP_HOSTNAME` was added** so a machine overlay can be tested without finding
a machine of that name. It also keeps captured documentation output generic.

**Stack detection reports the program name, not its path.** `cargo is on PATH`
rather than `/Users/someone/.cargo/bin/cargo`. The full path is noise, and on
someone else's machine it is different noise.

**`scripts/validate-examples.sh` never uses sudo.** An example declaring a
privileged path this account cannot create is reported as skipped, not failed.
CI provisions those paths itself before calling the script.

**Repo-root `tests/`.** The workspace root is also a never-published package
(`reap-tests`) so the integration tests can live at the repository root as the
layout in the prompt shows. This changes what a bare `cargo build` targets, so
`default-members` is set explicitly; without it `cargo build` builds only the
test harness. CI and CONTRIBUTING use `--workspace` regardless.

## Deferred

**Stripping `target/` from git history. DONE 2026-09-06.**
Commits M0 through M4 were made with `git add -A` before a `.gitignore` existed,
so 25,503 build-output files were committed and `.git` reached 849 MB. The owner
approved a history rewrite; `git filter-branch --index-filter` stripped `target/`
from all ten commits, followed by `reflog expire` and `gc --prune=now`.

Result: `.git` is 328 KB, no `target` path appears anywhere in history, all ten
commits are preserved, `git fsck` is clean and the 157 tests still pass. **Every
commit hash below M0 changed.** Nothing had been pushed, so this cost nobody
anything, but it must never be repeated after a push.

The `.gitignore` that prevents a recurrence landed in the first M5 commit.

**GitHub Actions runner labels, 2026-09-07.** The first CI run exposed that
`macos-13` no longer exists, so both x86_64 macOS jobs queued for 23 minutes and
had to be cancelled; `macos-14` is deprecated. Now on `macos-15` and
`macos-15-intel`, taken from the `actions/runner-images` README rather than
guessed. Worth re-checking whenever a runner image is retired.

**A test that depended on its host.** `doctor_passes_on_a_healthy_configuration`
asserted the string "Everything checks out", which only appears when there are
no warnings at all. The runner had 11.8% free disk, below the configured
low-water mark, so `doctor` warned and the test failed. `doctor` was right; the
test was wrong. It now asserts exit 0, the absence of a failure, and the
structural checks, and a separate test covers the low-disk path deliberately.

**`sweep --until-free` reported the wrong exit code, 2026-09-08.** It returned
the exit code of the last tier it ran, so a run that reclaimed at tier 0 and then
found tiers 1 and 2 empty exited 3, "nothing to do", after doing real work. Every
scheduled escalating sweep would have recorded work as no work. Exit codes are
now folded across tiers by precedence (config error, partial failure, work done,
nothing to do), with a regression test. Found by the systemd CI job on its first
run, which is the entire reason that job exists rather than a unit test
comparing generated unit text against expected unit text.
